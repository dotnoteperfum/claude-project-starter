# <프로젝트명> — PRD (제품 요구사항)

> 한 줄 요약: <이 제품이 무엇인지 한 문장. "누구를 위해, 무엇을, 어떻게 해주는 것">
> 작성일: <YYYY-MM-DD> / 작성자: <나> / 상태: <초안 / 확정>

---

## 1. 왜 만드나 (문제·배경)
- **해결하려는 문제**: <지금 무엇이 불편/비효율적인가>
- **누가 겪나**: <이 문제를 겪는 사람>
- **지금 어떻게들 하나**: <현재 방식 / 대안 — 그게 왜 부족한가>
- **왜 지금**: <이걸 지금 만드는 이유 / 계기>

## 2. 목표와 성공 기준
- **이루려는 것(목표)**: <이 제품이 성공하면 어떤 상태가 되나. 1~3개>
- **성공의 측정**: <숫자로. 예: "월 예약 30건", "DM 응답률 10%", "수작업 시간 절반">
- **❌ 목표가 아닌 것(Non-goal)**: <이번엔 안 하는 것 — 범위 폭주 방지용. 매우 중요>

## 3. 대상 사용자
- **주 사용자**: <누가 쓰나. 특징·상황>
- **사용 맥락**: <언제·어디서·어떤 기기로 쓰나 (폰? PC? 이동 중?)>
- **(있으면) 운영자/관리자**: <뒤에서 관리하는 사람과 그 니즈>

## 4. 핵심 시나리오 (사용자 흐름)
> "사용자로서 ___ 하고 싶다, 왜냐면 ___" 형태로. 가장 중요한 흐름 2~4개.
- <예: 손님으로서 폰으로 예약하고 싶다 → 링크 열기 → 날짜·인원 선택 → 제출 → 확인>
- <...>
- <...>

## 5. 기능 (우선순위별)
> P0 = 없으면 출시 불가(MVP) / P1 = 곧 필요 / P2 = 있으면 좋음. 처음엔 P0만 잘 추려도 충분.

| 우선순위 | 기능 | 한 줄 설명 |
|---|---|---|
| **P0** | <기능> | <뭘 하나> |
| P0 | <기능> | <...> |
| P1 | <기능> | <...> |
| P2 | <기능> | <...> |

## 6. 범위 밖 / 나중에
- <이번 버전에 안 넣는 것 (2번 Non-goal과 연결). "나중에 할 수도 있는 것" 포함>

## 7. 제약·가정
- **예산/비용**: <무료로 시작? 월 얼마까지?>
- **일정**: <언제까지 / 급한가>
- **플랫폼**: <웹? 앱? 둘 다? 특정 기기?>
- **법·정책**: <개인정보, 약관, 사업 규제 등 걸리는 것>
- **가정**: <"이건 이미 있다/된다고 전제" 하는 것들>

## 8. 기술 방향 (가벼운 메모 — 상세는 CLAUDE.md)
> 스택은 보통 여기서 확정 안 함. **알려진 제약·선호만** 적고, 정해지면 CLAUDE.md로.
- <예: "무료로 시작하고 싶음", "휴대폰 우선", "기존에 쓰던 ○○ 연동 필요" 등 / 없으면 "미정 — Claude 추천받기">

## 9. 리스크 & 미해결 질문
- ⚠️ <잘 안 될 수 있는 부분 / 불확실한 것>
- ❓ <아직 정해야 하는 질문 (정해지면 위 항목들에 반영)>

## 10. 단계 / 로드맵 (대략)
- **1단계 (MVP)**: <가장 작은 "그래도 쓸모있는" 버전 — P0 기능들>

- **3단계+**: <더 나중>
